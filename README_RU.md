# FotoMag — ТЗ № 4.8: бесплатная Windows-лаборатория GitHub Actions

**СТАТУС: ГОТОВЫ ФАЙЛЫ ДЛЯ ПУБЛИКАЦИИ; РЕПОЗИТОРИЙ ЕЩЁ НЕ СОЗДАН; WINDOWS RUN ЕЩЁ НЕ ВЫПОЛНЕН.**

## Зачем этот пакет

Проверить **официальную Desktop Commander v0.3.1** и лабораторную производную исправления **№ 4.6** на стандартном Windows runner GitHub Actions **без затрат**, не запуская ничего на рабочем компьютере FotoMag. Пакет не содержит клиентских файлов, паролей, локальных каталогов или имени рабочего ПК. Проверка кода на такие строки включена, но всё равно просмотрите содержимое перед публичной публикацией.

Исходный [пакет № 4.6](отдельный-файл-из-чата) остался неизменным и не публикуется этим комплектом. **Лабораторная производная не является побайтово тем же самым бинарником:** в Go и test-файлах заменён **только идентификатор защиты производственного ПК** на жёсткую проверку переменных `GITHUB_ACTIONS`, `RUNNER_OS` и `RUNNER_ENVIRONMENT`, чтобы код не мог запускаться вне GitHub-hosted Windows runner. Сам Windows desktop broker, выбор оболочки и передача stdout/stderr взяты из № 4.6. Для допуска к установке всё равно потребуются тесты исходного неизменённого пакета № 4.6.

## Как получить настоящий бесплатный Windows runner

1. В своей GitHub-учётной записи создайте **новый отдельный PUBLIC репозиторий**, например `dc-windows-console-lab`. Не используйте существующие рабочие приватные репозитории FotoMag, особенно Web-to-Print, Orchestrator и проект Open Source Lab в статусе PAUSED.
2. Разархивируйте этот комплект на любом **нерабочем** компьютере. Загрузите **всё содержимое корня пакета** в корень нового GitHub-репозитория (включая скрытую папку `.github`), а не единственный ZIP-файл. Сохраните структуру каталогов.
3. Проверьте, что репозиторий помечен как **Public**, затем откройте **Actions → DC v4.6 - Windows hosted functional evidence (NO deployment) → Run workflow**.
4. По окончании откройте конкретный запуск и скачайте **artifact `dc-v4-6-windows-functional-evidence`**. Содержимое: JSON для исходной версии, JSON для патча, stderr/stdout и итоговая оценка. Если тест завершился ошибкой, скачайте артефакт всё равно: он пишется через `if: always()`.
5. Передайте файлы артефакта в чат для оценки. **Никакие GitHub Actions результаты не могут сами дать разрешение установить патч на FotoMag.**

В workflow есть проверка `github.event.repository.private == false` и `visibility == public` **до выделения runner**. Приватный репозиторий не запускает job. Используется только стандартный `windows-2022`; нет larger runners, `secrets`, платных внешних сервисов, расписаний, автоматического trigger по push и продакшен-подключений. `workflow_dispatch` выполняется вручную, так что время и использование остаются под вашим контролем. По правилам GitHub стандартные GitHub-hosted runner **в публичных репозиториях** бесплатны. Актуальные правила: https://docs.github.com/en/actions/concepts/billing-and-usage .

## Что на самом деле выполняется на Windows

1. Проверяет public runner и статически сканирует собственные исходники на внутренние данные.
2. Клонирует **только публичный upstream** `wonderwhy-er/DesktopCommanderMCP` в двух отдельных каталогах с tag `v0.3.1`.
3. Сверяет git SHA исходного `src/utils/shell.ts` с известным значением `3d9c46e4a440afd8062cebf70864452bc1156d39`.
4. Применяет лабораторную копию патча № 4.6 к одному каталогу, проверяет неизменность других файлов и совпадение Go исходника.
5. Компилирует оба upstream checkout, отдельно компилирует экспериментальный Go Windows broker.
6. Выполняет Node.js unit-тесты планирования запуска и тест определения Windows сеанса.
7. Выполняет 100 попыток **baseline** и 100 попыток **broker** (10 сценариев × 10) в отдельной VM; получаются реальные stdout/stderr, коды выхода, PID и результаты.
8. Вызывает настоящий локальный API `improved-process-tools.startProcess` для трёх синтетических сценариев в обеих версиях; это ещё не Remote MCP по сети.
9. Сохраняет `CI_FINAL_VERDICT.json`. Этот файл **всегда** фиксирует `ready_to_deploy: false`, потому что Windows Actions runner не является доказанным интерактивным рабочим столом кассира FotoMag, полноценный Remote MCP E2E и проверка освобождения desktop handle не проведены.

## Чего CI НЕ доказывает

Даже 100/100 успешных subprocess tests **не доказывают** отсутствие видимых окон на реальном интерактивном рабочем столе и отсутствие перехвата фокуса. Сеансы GitHub-hosted runners часто не совпадают с активным пользовательским desktop. В комплекте есть API-проба `WTSGetActiveConsoleSessionId`, `OpenInputDesktop`, `GetProcessWindowStation` и `GetForegroundWindow`; она фиксирует доступность окружения, но не создаёт искусственный PASS. Не испытываются настоящая Remote MCP авторизация/переподключение, GUI диалоги, все дочерние процессы и полный жизненный цикл `CloseDesktop`.

Если исправленная версия выдаёт менее 100/100 функциональных PASS, это ценный технический FAIL; не переписывайте результаты и не устанавливайте её. Исходная версия может иметь сбои: это отдельно записывается.

## Вариант без GitHub: другая независимая Windows-машина

См. `GUI_FALLBACK_NO_RENT.md` и оригинальную инструкцию Windows из пакета № 4.6. Требуется **другой физический компьютер** с Windows 10/11 Pro или Windows Sandbox, не PRODUCTION-WORKSTATION. Эти инструменты могут использоваться только после явного контроля места запуска. Для интерактивных испытаний нужен реальный включённый GUI desktop; Linux runner ему не равен.

## Контроль безопасности

- На рабочем FotoMag запускать этот пакет **запрещено**.
- Запрещено публиковать ZIP № 4.6 целиком: его отчёты могут содержать внутренние сведения. Публичный комплект уже отфильтрован и снабжён дополнительными защитными проверками.
- Не добавляйте свои персональные токены, реальные фотографии, базы, дампы журналов из FotoMag или файлы `D:`.
- Workflow изолирован и не подключается к FotoMag Remote MCP; `GITHUB_TOKEN` ограничен `contents: read`, а сохранение учётных данных checkout отключено.
- Если GitHub показывает платный runner, private repo или требует платежи — **не запускайте**.
